## 🎯 Razorpay Buildathon & Interview Talking Points

### 1. "What makes Mercury an AI Agent platform rather than an LLM chatbot?"
> *"The LLM never directly executes financial or payment actions. Instead, the AI agent acts as a planner using typed tools. Every proposed transaction passes through an air-gapped, deterministic Policy Engine. If an action exceeds merchant boundaries (e.g. ₹15,000 discount request), the Policy Engine blocks it, generates an AI ROI rationale, and routes it to human merchant approval."*

### 2. "How do you handle Razorpay payment security and verification?"
> *"Order creation is strictly server-side (`RazorpayService.createOrder`). When the client completes checkout, payment signature verification is executed on the server using HMAC-SHA256 algorithm matching `razorpay_order_id`, `razorpay_payment_id`, and `razorpay_signature`. Only upon valid signature verification is the order state transitioned to `CAPTURED` in SQLite."*

### 3. "How do you measure incremental revenue for Track 01?"
> *"We separate Total Store Revenue from AI-Influenced Order Value and Incremental AI Upsell Revenue. Incremental revenue is defined strictly as additional revenue generated by co-purchase upsells accepted by the buyer during an agentic session."*
